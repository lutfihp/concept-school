# Deployment Guide — Sekolah Bina Pandu Utama

**Date:** 2026-06-11  
**Status:** Approved

## Goal

Produce a `DEPLOYMENT.md` at the project root that serves as a self-contained, repeatable guide for building and deploying this static Next.js site to a VPS via FileZilla.

## Output File

`DEPLOYMENT.md` — project root (not inside `docs/`). Written once, referenced on every deploy.

## Audience

The site owner (non-daily developer). Assumes SSH access to VPS, FileZilla installed locally, nginx + certbot already installed on VPS.

## Document Structure

### Section 1 — Prerequisites
- Checklist of what must exist before running any steps:
  - Node.js + npm installed locally
  - VPS with SSH access
  - nginx installed on VPS
  - certbot installed on VPS
  - Subdomain DNS A-record pointing to VPS IP

### Section 2 — First-Time VPS Setup (run once)
Steps performed via SSH on the VPS:

1. Create web root and set ownership:
   ```bash
   sudo mkdir -p /var/www/concept-school
   sudo chown -R www-data:www-data /var/www/concept-school
   sudo chmod -R 755 /var/www/concept-school
   ```

2. Create nginx server block at `/etc/nginx/sites-available/concept-school`:
   ```nginx
   server {
       listen 80;
       server_name YOUR_SUBDOMAIN;
       return 301 https://$host$request_uri;
   }

   server {
       listen 443 ssl;
       server_name YOUR_SUBDOMAIN;

       root /var/www/concept-school;
       index index.html;

       location / {
           try_files $uri $uri.html $uri/ =404;
       }

       error_page 404 /404.html;
   }
   ```

3. Enable the site and test:
   ```bash
   sudo ln -s /etc/nginx/sites-available/concept-school /etc/nginx/sites-enabled/
   sudo nginx -t
   sudo systemctl reload nginx
   ```

4. Obtain SSL certificate with certbot:
   ```bash
   sudo certbot --nginx -d YOUR_SUBDOMAIN
   ```
   Certbot rewrites the nginx config with SSL directives automatically.

5. Reload nginx:
   ```bash
   sudo systemctl reload nginx
   ```

### Section 3 — Initial Deploy (first file upload)

**Local (Windows terminal):**
```
npm run build
```
This produces the `out/` directory — do not upload the folder itself, only its contents.

**FileZilla steps:**
1. Connect to VPS (Host: VPS IP, Protocol: SFTP, Port: 22)
2. Navigate remote to `/var/www/concept-school`
3. Navigate local to the `out/` folder inside the project
4. Select all files and folders inside `out/`, drag to remote
5. Wait for transfer to complete

**Back on VPS (SSH) — fix permissions:**
```bash
sudo chown -R www-data:www-data /var/www/concept-school
```

**Verify:** Open `https://YOUR_SUBDOMAIN` in a browser.

### Section 4 — Re-deploy After Changes (repeat every time)

1. Edit source files locally
2. Run `npm run build` — fresh `out/` is produced
3. FileZilla: connect, navigate to `/var/www/concept-school` on remote
4. **Delete all existing files on the remote first** (select all → Delete)
5. Re-upload all contents of `out/`
6. Fix permissions on VPS:
   ```bash
   sudo chown -R www-data:www-data /var/www/concept-school
   ```
7. Verify in browser — no nginx reload needed for static file changes

## Notes

- `out/` is gitignored — it is always regenerated from source. Never commit it.
- The `YOUR_SUBDOMAIN` placeholder must be replaced with the real subdomain everywhere in the nginx config and certbot command.
- The locale redirect (`/` → `/id`) is handled by `out/index.html` which is a static redirect page generated by Next.js.
- Next.js static export uses `.html` files for routes (e.g. `/id` is served from `id.html`). The nginx `try_files $uri $uri.html` directive handles this.
